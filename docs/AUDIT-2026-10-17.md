### 数据与安全边界

- 应用阅读窗口关闭 Node，开启上下文隔离与沙箱；自定义协议限制资源目录，IPC 仅允许明确业务类型。外部 HTTP/S / 邮件链接需确认，不允许文献直接读取任意磁盘路径、执行代码或任意开窗口。
- Windows 应用 Key 通过 Electron `safeStorage` / 系统 DPAPI 保存；加密不可用则拒绝保存，不回退明文。设置读取与变更广播均脱敏。插件仍使用浏览器扩展本地存储或可选明文 `config.local.json`，不能声称它也采用应用版 DPAPI。
- 安装包不自动读取源码 Key，仅源码开发模式显式传入开发配置路径才允许加载。分发排除本地配置、真实用户 PDF、测试用户目录和开发内容；最终包需另做源码一致性与密钥检查。
- 备份 ZIP 未加密，包含 PDF、原文片段、笔记和讨论，不主动包含 API 设置或 Key。恢复校验 ZIP 结构、路径、CRC、PDF SHA-256、页码、记录和排版边界，完整验证后原子合并；较新本机记录优先。
- 书签 / 笔记在锁内合并页面修改；对话使用 `pdf-chat-state:${documentId}` WebLock 和基线比较，阻止旧窗口覆盖更新。晚到写入不能复活已删除文档。读取历史失败时阻止盲目覆盖；保存失败可导出并重试，严格 flush 向离开 / 备份流程报告异常。
- 对话后台校验阅读器顶层来源、请求大小、历史角色、页码及并发；取消限定发起窗口 / 文档。文献文本只作不可信证据，输出按安全文本渲染，不执行模型 HTML 或脚本链接。SSE 的响应体阶段受超时与取消约束，截断 / 断流保留为未完成，不自动重试或切免费服务。
- 已复现本机 Electron 在原 OneDrive 中文运行目录中启动失败，改用非 OneDrive 英文目录；默认安装目标 `%LOCALAPPDATA%\Programs\PaperTranslator`，可保留中文快捷方式和 PDF 文件名。应用无代码签名、无自动更新下载；不以关闭安全软件解决启动提示。

## 用户真实问题复现 · 1.2.1

本节优先于历史验收结果。用户提供 `s41467-020-18353-4.pdf`（13 页）与两张截图，指出串栏、混杂原文、孤立的 fi 和被误译的数学下标。此前的合成 PDF + 通用 mock 译文不能覆盖这些问题。

- 根因：按字形顶部而非基线聚行；字体 ascent=0 将连字拆出；约 12pt 的栏缝小于原来的 1.5 倍字号阈值；上下标被当成独立块；后绘制的矩形遮罩可擦除前段译文。
- 新布局：基线行、大小字关联、首字下沉、跨行断词、持续栏缝投票/文字覆盖率、按栏阅读顺序、图注横跨整页分区。数学下标用变量记法保留，单位负指数不作为引用编号。
- 新绘制：分两轮擦除/写字，加入其他文字块的碰撞保护、字号下限、标题字重及中文标点换行。无法安全放置的译文保留原文并标注；并未改成出版级原生 PDF 重排。
- 参考文献书目、作者/页眉页脚及细小图内文字保留原样；图像型导出的原有限制不变。新缓存签名包含布局版本，不复用 1.2.0 结果，也不删除原 PDF 副本。
- 翻译链路：给自定义模型提供标题、摘要、前后段原文和先前译文，源段落独立放入 user 消息；上下文长度受限并参与缓存键。截断输出或长英文未译为中文的结果不记完成；全文禁用 SSE 卡片推送。

## 功能问题（按优先级）

### 1. [P1] 连续缩放会使当前页丢失渲染

- 位置：`src/viewer.js:440`、`src/viewer.js:460`、`src/viewer.js:581`。
- 复现：正常加载样例 PDF 后，连续触发两次放大，等待 1.2 秒。
- 结果：页面条目仍存在，但 canvas 和文字层数量都为 0，条目只剩“第 1 页”占位。截图 `dev/test/artifacts/audit-zoom.png`。
- 原因：第一次缩放发起渲染；第二次增加 `gen`，使旧任务失效，但 `rendering` / `pending` 阻止新任务入队。旧任务退出后没有保证重新渲染当前可见页。
- 修复方向：渲染任务绑定文档与缩放代次；取消旧任务后，对仍可见且未渲染的条目重新调度。不要只靠 IntersectionObserver 再次触发。

### 2. [P1] PDF 透明文字层的宽度校正没有实际执行

- 位置：`src/viewer.js:354`、`src/viewer.js:359`、`src/viewer.js:497`。
- 复现：读取样例 PDF 的文本 span 的目标宽度、实际宽度与 transform。
- 结果：一行目标宽度约 827px，实际宽度 877px，但 transform 为空；另一行目标约 571px，实际 595px，同样没有校正。
- 原因：`span.offsetWidth` 在整个 layer 尚未挂入文档时读取，为 0，全部跳过；插入文档后没有再次校正。
- 影响：可见文字和真正能选中的位置不一致，长句、不同字体和高倍缩放时更明显。
- 修复方向：使用 pdf.js 正式文字层实现，或在挂载、字体就绪后按正确字体度量校正，并覆盖旋转/CJK 场景。

### 3. [P1] 重复选中相同文本会丢掉 AI 升级；最终质量请求也会误用免费缓存

- 位置：`src/background.js:664`、`src/background.js:717`、`src/background.js:752`。
- 复现：A 请求先拿到免费结果、AI 升级尚未完成时，B 再请求同一句；同时请求 `quality: true`。
- 结果：A 收到 AI 升级，B 只拿到免费缓存，而且没有 `provisional` 标识，也收不到升级。`quality: true` 同样立即返回免费缓存。
- 原因：缓存没有“临时/最终”质量信息；升级只保存第一个请求的回调；缓存命中发生在质量策略判断之前。
- 影响：反复划词、多个标签页、剪贴板翻译可能得到不一致或不再升级的结果。
- 修复方向：缓存显式区分质量；共享请求维护订阅者集合；最终质量请求等待或重新获取最终结果。

### 4. [P1] 请求超时和取消只覆盖响应头，不覆盖响应体

- 位置：`src/background.js:258`、`src/background.js:276`。
- 复现：模拟 fetch 已返回响应头，随后超过设定期限并取消外部 signal。
- 结果：内部请求 signal 仍未 aborted。
- 原因：`await fetch()` 返回响应对象就进入 finally，提前清掉超时和外部取消监听；之后的 `res.json()` / SSE `reader.read()` 不再受该超时控制。
- 影响：服务器发送响应头后卡住时，界面可能长期“生成中”，请求无法按预期取消。
- 修复方向：将超时及取消生命周期延伸到响应体读完，并处理流读取失败和 reader 清理。

### 5. [P2] PDF 跨行整句翻译会粘连单词

- 位置：`src/viewer.js:189`、`src/viewer.js:322`。
- 复现：在样例 PDF 的第二段选中 `select`，使用整句扩展。
- 实际原文：`Second paragraph: select any sentence with the mouse and thetranslation card should appear immediately next to your selection.`
- 原因：文本模型补入了虚拟行间空格，但最终又通过 DOM Range 的 `toString()` 取文本，虚拟空格随之丢失。
- 修复方向：从规范化模型中提取待翻译文本，Range 仅负责高亮；同时处理跨行断词、段落边界与双栏阅读顺序。

### 6. [P2] 普通网页的“整句”模式不能补全首句开头

- 位置：`src/content.js:300`、`src/content.js:307`。
- 复现：样例网页第一句只选 `fox jumps`。
- 实际结果：`fox jumps over the lazy dog.`，缺少 `The quick brown`。
- 原因：向前找不到标点时，起点仍保持原选区起点，不会回到块的开头；遇到内联标签时，选择的文本容器也可能过小。
- 修复方向：在合理长度和语义块范围内回退到句首，并使用上下文判断句号、缩写和数字，不要逐个字符测试依赖后视上下文的正则。

### 7. [P2] 阅读器没有同步外部设置；字号设置被 CSS 覆盖

- 位置：`src/viewer.js:103`、`src/viewer.js:115`、`src/viewer.css:392`。
- 复现一：设置页修改目标语言后，已打开阅读器仍显示旧语言，且翻译请求使用阅读器中的旧设置。
- 复现二：字号设为 22px 后重新打开阅读器，卡片根节点计算字号为 22px，但译文节点仍为 15px。
- 原因：阅读器只在启动时读取设置，没有监听 storage 变化；译文 CSS 固定为 15px，覆盖继承字号。
- 修复方向：建立统一设置订阅，避免跨页面全量覆盖；译文字号使用继承或 CSS 变量。

### 8. [P2] “测试翻译/测速”不能可靠验证自定义 API

- 位置：`src/background.js:916`、`src/options.js:170`、`src/options.js:184`。
- 复现：模拟自定义 API 返回 401，免费引擎成功，再调用设置页使用的翻译入口。
- 结果：仍然得到 `ok: true`、免费引擎译文和 `provisional: true`。
- 原因：`testTranslate` 没有强制最终质量或禁止免费兜底；测速将“原本想测试的引擎”与“真正返回结果的引擎”混用，也可能命中旧缓存。
- 影响：Key 或地址配置错误也可能显示测试成功；所谓“自定义引擎耗时”可能其实是免费引擎耗时。
- 修复方向：提供专用 provider 探测入口，固定引擎、禁缓存、禁升级和兜底；测速默认只展示结果，不悄悄改变用户的翻译策略。

### 9. [P2] MyMemory 错误处理和分片单位不正确

- 位置：`src/background.js:349`、`src/background.js:351`、`src/background.js:385`。
- 复现一：模拟 HTTP 200，但 JSON 内 `responseStatus: 403`、`translatedText` 为配额警告。
- 结果：警告被作为正常译文返回，可能在竞速中抢先胜出。
- 复现二：200 个汉字作为一个分片，实际 UTF-8 为 600 字节，已超过接口约 500 字节上限。
- 原因：未检查业务状态码；限制按 JS 字符串长度计算，而不是 UTF-8 字节数。
- 修复方向：检查业务响应状态和内容，按字节安全切片，控制长文本分片并发。

### 10. [P2] 本地配置的地址和密钥保存行为与说明不符

- 位置：`src/background.js:113`、`src/background.js:122`、`src/background.js:960`、`src/options.js:55`、`src/options.js:109`。
- 全部使用虚构配置和假 Key 验证，没有输出真实 Key。
- 复现一：本地配置填写其他 Base URL，浏览器无显式设置，生效地址仍为默认 DeepSeek 地址。
- 原因：先填入非空默认地址，再判断地址是否为空，因此本地地址无法覆盖默认值；Key 却会被读入，可能形成地址和凭据不匹配。
- 复现二：触发安装回调后，解析得到的本地 Key 被写入浏览器 storage；设置页也会回填有效 Key，并在自动保存其他字段时再次存入。
- 影响：不符合注释中“不想把 Key 存进浏览器配置”的承诺。这不是本轮发现的 Git 泄密。
- 修复方向：区分默认值、显式设置和本地兜底；地址、模型和凭据按同一配置来源解析；UI 使用“已配置”状态，不把本地秘密回填后自动持久化。

## 界面和体验问题

1. **阅读器工具栏缺少主次。** 文件、翻页、缩放、语言、引擎、行为开关和文件操作全堆在一排；字号和点击区域偏小。应分出文档导航、阅读操作、翻译偏好三个层级。
2. **窄窗口确实截断控件。** 390px 宽时工具栏高约 154px；语言/引擎/开关组不能自行换行，右侧“选中即译”被裁切。不是仅仅“不够美观”。截图 `audit-mobile.png`。
3. **设置页像开发调试表单。** JSON、思考参数、系统提示词与常用语言设置同样突出，大段说明抢占视线。建议常用设置优先，高级 API 参数折叠，状态就地反馈。
4. **弹窗入口过多。** 打开当前 PDF、强行打开任意地址、本地文件、剪贴板及全部行为开关并列，缺少清晰主任务。应按当前标签页状态只突出一个主入口。
5. **翻译卡片遮挡后续原文。** 现有卡片虽能显示结果，但工具、状态、原文、译文层级较弱。可以保留紧凑划词卡片，同时提供可选侧栏，不强制大面积遮住论文。
6. **文案落后于实现。** 设置页仍写“Google → Microsoft 依次尝试”，弹窗页脚及 PDF 提示仍写 `Alt+Shift+Z/X`，与实际注册的 `Alt+Z/X` 不一致。

视觉改版建议采用清爽、克制、适合长时间阅读的文献工具方向：稳定的页面留白、统一的间距/字体/边框、明确的主按钮、折叠的高级配置，以及不干扰阅读的状态反馈。先改信息架构，再统一视觉，不只替换颜色。

## 建议实施顺序

1. 修复缩放调度、文字层度量和跨行取词；补实际鼠标选择、连续缩放及跨行断言。
2. 修复临时/最终缓存、订阅分发、请求取消及真实引擎测试；补并发标签页、重复选句、401、限额与停滞 SSE 用例。
3. 修复设置同步、字号和配置来源处理。
4. 重整阅读器工具栏、卡片、弹窗与设置页，统一设计变量，并验证窄窗口、深浅主题与键盘操作。
5. 将本轮可复现诊断整理成正式测试。同步更新测试启动方式和交接文件，不再仅用旧的 17 项冒烟断言代表整体质量。

## 仍未完整验证

- 加密/密码 PDF、扫描 PDF、双栏学术论文、旋转文本、复杂 CJK 与 1000 页级文档。
